Os erros da API de integração chegam no formato abaixo, com um ou mais itens em `errors`:

```json
{
  "success": false,
  "errors": [
    {
      "code": 149,
      "message": "Não há motoristas por perto"
    }
  ]
}
```

Os códigos são os mesmos na v1 e na v2: as rotas da v2 que repassam a operação para a v1 devolvem o `code` da v1 sem alteração.

> **Trate o erro pelo `code`, e não pelo texto**: a `message` muda conforme o tipo da central ("motorista" pode vir como "taxista", "mototaxista" ou "entregador"; "passageiro" como "cliente"), e alguns textos trazem valores dinâmicos, como `{campo}`, `{valor}` e `{maximo}`.

## Códigos especiais

| code | Quando ocorre |
|---|---|
| `0` | Erro inesperado no processamento ("Falha na operação"), ou erro que ainda não tem código próprio. Nesse caso, a `message` descreve o motivo. |
| sem `code` | Na v1, os erros de chave de acesso e de método HTTP chegam como uma lista de textos: `"errors": ["Chave da API inválida."]`. |
| `B1` a `B6` | Na v2, os erros de chave de acesso e de usuário trazem um `code` em texto. Veja a tabela abaixo. |
| `401`, `404` e `503` | Em algumas rotas da v2 que não repassam a operação para a v1 (como mensagens da corrida e posição de condutores), o `code` repete o status HTTP: credenciais inválidas (`401`), corrida que não pertence à central (`404`) e serviço indisponível (`503`). |

### Autenticação na v2

| code | HTTP | Mensagem | Quando ocorre |
|---|---|---|---|
| `B1` | 400 | Chave da api não informada. | Nenhuma chave enviada no header. |
| `B2` | 400 | Desculpe, não foi possível entender sua solicitação. | `api-key` e `app-key` enviadas juntas. |
| `B3` | 401 | Você não está autorizado a acessar este recurso. | Só a `app-key` foi enviada, sem a `api-key`. |
| `B4` | 401 | Você não está autorizado a acessar este recurso. | `api-key` inexistente. |
| `B5` | 401 | Usuário e/ou senhas inválidos. | Login ou senha do Basic Auth inválidos. |
| `B6` | 403 | Você não tem permissão para acessar este recurso. | Rota exclusiva de empresa chamada por usuário sem empresa vinculada. |

## Autenticação e permissão

| code | Mensagem | Quando ocorre |
|---|---|---|
| `1` | Usuário e/ou senhas inválidos. | Login ou senha do Basic Auth inválidos, ou usuário inativo. |
| `19` | Não é possível utilizar a API com a sua licença. | Plano da central sem a funcionalidade de integração via API (ou da API V2, nos endpoints de empresas/condutores em lote). |
| `63` | Você não tem permissão para realizar essa operação. | Usuário de empresa chamando endpoint exclusivo da central. |
| `67` | O usuário informado não pode realizar essa operação. | Tipo de usuário não pode chamar a operação (ex.: usuário de empresa em operação de central). |
| `68` | O usuário informado não tem permissão para realizar essa operação. | Usuário sem a permissão de integração exigida pelo endpoint. |
| `68` | O usuário informado não tem permissão para realizar essa operação. | Usuário sem a permissão de cupom, ou central que não faz somente entregas na exclusão de parada. Só na v2. |

Alguns códigos foram publicados com mais de um significado e não podem ser renumerados sem quebrar integrações existentes. Nesses casos, use o endpoint chamado para saber qual é o erro.

| code | Significados |
|---|---|
| `43` | Data de nascimento inválida, na atualização do motorista; tipo de pagamento inválido para a empresa, na criação de entrega e no cadastro de empresa. |
